# Larnix — workspace agent guide

Refines the global guide. Roles are unchanged: Claude plans and reviews, Codex implements.

## Repository facts

- Static site; no runtime dependencies. Build with `python3 scripts/build_site.py`; serve
  `dist/` with `python3 -m http.server 8775 --bind 127.0.0.1 --directory dist`.
- `make check` is the acceptance gate: curriculum validation, Node engine and platform tests,
  JavaScript syntax checks, Python unit tests, data-lab tests. CI runs the same plus
  `codespell` and the rendered-link test. Install `labs/data-foundations/requirements.txt`
  in a virtual environment first.
- Authoritative records: `docs/curriculum/curriculum.json` and `sources.json`. All Markdown
  under `docs/curriculum/` except `README.md`, `TEACHING_DESIGN.md` and `REVIEW_*.md` is
  generated by `python3 scripts/curriculum.py render`; never hand-edit it.
- Preview availability comes only from `web/lessons.json`. A lesson is `preview` only when
  the manifest lists it; `complete` only with nine named evidence files. The checker enforces
  both. Never change a status to make a page look finished.
- Branches: `codex/<slug>` from `main`; PR to `main`; the four CI check names in
  `.github/workflows/checks.yml` must stay. Nothing is pushed to `main` directly.

## Ticket types for this project

| Ticket | Codex delivers | Claude reviews against |
| --- | --- | --- |
| Author a lesson preview | notes in `samples/foundations/*.json` or a `samples/<slug>/` lab, manifest entry with answer keys, tests added to `make check`, status set to `preview`, docs regenerated | the nine-part lesson contract in `docs/curriculum/README.md`, the teaching sequence in `TEACHING_DESIGN.md`, topic coverage of the plan, synthetic data labelled as such, no overclaim in prose |
| Change a lesson plan | edits to `curriculum.json` or `sources.json`, regenerated Markdown, updated tests | prerequisite closure, teaching order, learning-route validator, source policy (primary sources, pinned versions) |
| Platform change | `web/`, `scripts/`, `tests/` edits with tests | no new runtime dependency, both themes, keyboard access, narrow-screen layout, progress-storage rules |
| Lab or exercise | runnable artifact with tests, injected failure, README with reproduce steps and limits | determinism, pinned versions exist, no network use, honest "what this does not show" |

## Evidence a Larnix ticket must return

- `make check` output on the final head, and the build line showing counts.
- For lessons: the lesson ID, manifest entry, answer keys matched to authored answers, and a
  browser check at desktop and 390 px width with no console errors.
- For plan changes: the structural delta (lessons added or changed, prerequisites, sources)
  and the recomputed transitive prerequisite count for any lesson whose prerequisites changed.
- Any claim of learner validation must name the study; otherwise write "not learner-validated".

## Review checklist additions

- Originality: no text, fixtures, diagrams or code imported from the reference playbook or
  any third-party course.
- Every number in README or docs that counts lessons, previews or sources matches the records.
- Generated files were regenerated, not edited, and `curriculum.py check` passes.
- Teaching order and prerequisites make pedagogical sense for the learner route, not only
  pass the validator.

## Artifact layout for a Task

```text
<initiative>/index.md                               kind: story
<initiative>/plan.md                                kind: spec    (scope, sequence, decisions)
<initiative>/t<n>-<lesson-or-slug>/index.md         kind: ticket
<initiative>/t<n>-<lesson-or-slug>/review-r<k>.md   kind: review
```
