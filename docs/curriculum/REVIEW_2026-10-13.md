## Post-review corrections to b584ff0

The two medium findings were valid. The repeated `estimate_basis` fields have been removed from all records, generated prose and the learner's Practice time panel. The differentiated hour ranges are retained with a shared, explicit warning that they are uncalibrated estimates. The earlier claim of a documented per-lesson estimation basis has been withdrawn. Prerequisites now describe knowledge dependencies independently of catalogue numbering. Catalogue IDs and URLs are unchanged. Generated module plans, classroom lists and next/previous navigation all use this order.

Counts exclude the target lesson and deduplicate the full dependency graph. The hardware prerequisite differs from the review's suggestion deliberately: M35-L01 is specifically about LLM serving, so using it would still put hardware basics behind LLM APIs and serving economics. Arrays and a tensor learning step supply the knowledge needed for the hardware worksheet. Edge parity testing needs a trained model and evaluation data, not a batch/online serving lifecycle.

To make the tracking route independent end to end, packaging (M29-L01) now starts from software and evaluation foundations. The reliability prerequisite moves to progressive release (M29-L03), where rollback and service failure behavior are actually needed. Feature engineering no longer requires orchestration; labeling strategy no longer requires feature stores; explainability no longer requires HPO. Forecasting does not require recommendation systems.

The [predictive-ML route](LEARNING_PATH.md#predictive-ml-engineering) is now an explicit lesson-level selection expanded to include every transitive prerequisite. Its validator rejects accidental transformer/retrieval/agent dependencies, including indirect ones. It does not promise that advanced LLM serving or every lesson in the containing modules belongs to this route.
