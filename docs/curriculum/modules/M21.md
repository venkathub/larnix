## M21-L01 — Define persistent execution state

**Delivery:** planned · full lesson contract: not_met · interaction: none · artifact: none

**Prerequisites:** [M20-L04](M20.md#m20-l04)

**Learning outcome:** Separate durable state from transient model context.

**Topics:** state schemas; checkpoints; event logs; reducers; versioning.

**Study estimate:** 2–3 hours guided study + 3–5 hours exercise. These are uncalibrated learner-effort estimates, not measured timings or an implementation schedule.

### Primary readings

- [STATE: LangGraph persistence](https://docs.langchain.com/oss/python/langgraph/persistence) — Checkpoints, threads, replay, persistent state.

### Interview question

What must persist to resume an interrupted agent safely?

**A strong answer addresses:** Decision state; pending actions; tool receipts; schema version.

Score 0–3 using the [shared interview rubric](../README.md#interview-rubric).

### Production exercise

Implement a checkpoint store and reconstruct an evidence-gathering agent from persisted state.

**Acceptance criteria:**

- Reconstruct progress from persisted records.
- Exclude secrets and avoid storing redundant raw content.

**Evidence to submit:**

- Versioned artifact or design specification.
- Baseline or hand-checkable fixture.
- Results or expected-results table including a failure case.
- Decision and limitations note.

**Resources:** CPU/local fixtures or a mocked provider; live service use is optional.
