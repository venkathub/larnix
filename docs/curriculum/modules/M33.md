## M33-L01 — Diagnose an adaptation need

**Prerequisites:** [M08-L04](M08.md#m08-l04), [M25-L04](M25.md#m25-l04)

**Learning outcome:** Tie adaptation to a measured behavioral failure.

**Topics:** prompting versus RAG versus tuning; task definition; baselines; data sufficiency.

**Study estimate:** 1–2 hours guided study + 2–4 hours exercise. These are learner-effort estimates, not an implementation schedule.

### Primary readings

- [PEFT: Hugging Face PEFT](https://huggingface.co/docs/peft/index) — Adapters, efficient tuning, quantization integration.
- [EVAL: OpenAI evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices) — Task-specific datasets, graders, human calibration, continuous evaluation.

### Interview question

When should you fix the dataset instead of fine-tuning again?

**A strong answer addresses:** Label quality; target mismatch; evaluation evidence.

Score 0–3 using the [shared interview rubric](../README.md#interview-rubric).

### Production exercise

Write an adaptation proposal for inconsistent damage-category extraction.

**Acceptance criteria:**

- Show baseline errors.
- Specify success criteria and a no-tuning alternative.

**Evidence to submit:**

- Versioned artifact or design specification.
- Baseline or hand-checkable fixture.
- Results or expected-results table including a failure case.
- Decision and limitations note.

**Resources:** Tiny/local model, synthetic media, or supplied recorded outputs/profiles; larger GPU or paid-provider runs are optional. Replay analysis cannot establish real hardware performance.

**Topics:** instruction formats; chat templates; label masking; packing; splits; contamination.

**Study estimate:** 1–2 hours guided study + 2–4 hours exercise. These are learner-effort estimates, not an implementation schedule.

### Primary readings

- [PEFT: Hugging Face PEFT](https://huggingface.co/docs/peft/index) — Adapters, efficient tuning, quantization integration.

### Interview question

Why can training on assistant delimiters or user text incorrectly distort results?

**A strong answer addresses:** Loss masking; serialization; objective.

Score 0–3 using the [shared interview rubric](../README.md#interview-rubric).

Create a small original instruction dataset and implement template, loss-mask and contamination checks.

**Acceptance criteria:**

**Prerequisites:** [M33-L02](M33.md#m33-l02)

**Learning outcome:** Explain the memory and capacity tradeoffs of adapter tuning.

**Topics:** LoRA; QLoRA; rank; target modules; quantization; hyperparameters; checkpoints.

**Study estimate:** 1–2 hours guided study + 2–4 hours exercise. These are learner-effort estimates, not an implementation schedule.

### Primary readings

- [PEFT: Hugging Face PEFT](https://huggingface.co/docs/peft/index) — Adapters, efficient tuning, quantization integration.

**Acceptance criteria:**

## M33-L04 — Distill and release adapted models

**Prerequisites:** [M33-L03](M33.md#m33-l03)

**Learning outcome:** Transfer useful behavior while tracking inherited errors and use permissions.

**Topics:** teacher outputs; data filtering; task distillation; adapter merge; regression; deployment.

**Study estimate:** 1–2 hours guided study + 2–4 hours exercise. These are learner-effort estimates, not an implementation schedule.

### Primary readings

- [TRL: Hugging Face TRL](https://huggingface.co/docs/trl/index) — SFT, reward modeling, DPO, GRPO, distillation.
- [PEFT: Hugging Face PEFT](https://huggingface.co/docs/peft/index) — Adapters, efficient tuning, quantization integration.
- [EVAL: OpenAI evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices) — Task-specific datasets, graders, human calibration, continuous evaluation.

### Interview question

How can distillation preserve a teacher's mistakes?

**A strong answer addresses:** Synthetic-label bias; limited task coverage; evaluation.

Score 0–3 using the [shared interview rubric](../README.md#interview-rubric).

### Production exercise

Run or replay a teacher-to-small-model experiment with human-audited synthetic examples and independent held-out evaluation.

**Acceptance criteria:**

- Record generation provenance and permitted use.
- Compare student, teacher and untuned baseline on unseen cases.

**Evidence to submit:**

- Versioned artifact or design specification.
- Baseline or hand-checkable fixture.
- Results or expected-results table including a failure case.
- Decision and limitations note.

**Resources:** Tiny/local model, synthetic media, or supplied recorded outputs/profiles; larger GPU or paid-provider runs are optional. Replay analysis cannot establish real hardware performance.
