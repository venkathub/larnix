## M15-L01 — Establish exact search

**Prerequisites:** [M14-L04](M14.md#m14-l04), [M02-L04](M02.md#m02-l04)

**Learning outcome:** Build the comparison target for approximate retrieval.

**Topics:** nearest neighbors; distance metrics; brute force; filter semantics; ground truth.

**Study estimate:** 1–2 hours guided study + 2–4 hours exercise. These are learner-effort estimates, not an implementation schedule.

### Primary readings

- [FAISS: Faiss research and documentation](https://github.com/facebookresearch/faiss/wiki) — Similarity metrics, approximate indexes, IVF, HNSW, quantization.
- [PGVECTOR: pgvector documentation](https://github.com/pgvector/pgvector) — Postgres vector search, filtering, approximate indexes, hybrid search.

### Interview question

Why must ANN recall be measured against exact search with the same filters?

**A strong answer addresses:** Candidate universe; metric consistency.

Score 0–3 using the [shared interview rubric](../README.md#interview-rubric).

### Production exercise

Implement an exact-search harness over synthetic vectors with metadata filters and hand-checkable distances.

**Acceptance criteria:**

- Verify distances on a small fixture.
- Return only permitted candidates.

**Evidence to submit:**

- Versioned artifact or design specification.
- Baseline or hand-checkable fixture.
- Results or expected-results table including a failure case.
- Decision and limitations note.

**Resources:** CPU/local fixtures or a mocked provider; live service use is optional.

## M15-L04 — Isolate and maintain indexes

**Prerequisites:** [M15-L03](M15.md#m15-l03)

**Learning outcome:** Define isolation and recovery tests for a mutable vector store.

**Topics:** tenant partitioning; ACL filters; replication; compaction; deletion; reindexing.

- [PGVECTOR: pgvector documentation](https://github.com/pgvector/pgvector) — Postgres vector search, filtering, approximate indexes, hybrid search.

### Interview question

**Acceptance criteria:**

- Prove zero cross-tenant IDs in test results.
- Test restored permissions and deleted-record exclusion.

**Evidence to submit:**

- Versioned artifact or design specification.
- Baseline or hand-checkable fixture.
- Results or expected-results table including a failure case.
- Decision and limitations note.

**Resources:** CPU/local fixtures or a mocked provider; live service use is optional.
