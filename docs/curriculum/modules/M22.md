## Module outcomes

- Assign each remembered fact an owner, lifetime and purpose.
- Validate memory candidates before committing them.
- Use relevant memory while honoring current facts and deletions.
- Measure whether memory helps the intended user without leaking other users' data.

## M22-L01 — Separate memory types

**Delivery:** planned · full lesson contract: not_met · interaction: none · artifact: none

**Prerequisites:** [M12-L04](M12.md#m12-l04), [M21-L04](M21.md#m21-l04), [M06-L04](M06.md#m06-l04)

**Learning outcome:** Assign each remembered fact an owner, lifetime and purpose.

**Topics:** working state; episodic memory; semantic memory; preferences; procedural knowledge.

**Study estimate:** 1–2 hours guided study + 2–3 hours exercise. These are uncalibrated learner-effort estimates, not measured timings or an implementation schedule.

### Primary readings

- [CONTEXT: Anthropic context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) — Context selection, compaction, long tasks, external memory.
- [NIST: NIST AI risk management framework](https://www.nist.gov/itl/ai-risk-management-framework) — Governance, risk identification, measurement and management.

### Interview question

Why should conversation history not automatically become long-term memory?

**A strong answer addresses:** Consent; noise; relevance; sensitive information.

Score 0–3 using the [shared interview rubric](../README.md#interview-rubric).

### Production exercise

Create a memory policy for a rental assistant using synthetic preferences and past incidents.

**Acceptance criteria:**

- Classify each field.
- Define what stays transient and what requires explicit persistence.

**Evidence to submit:**

- Versioned artifact or design specification.
- Baseline or hand-checkable fixture.
- Results or expected-results table including a failure case.
- Decision and limitations note.

**Resources:** CPU/local fixtures or a mocked provider; live service use is optional.

**Prerequisites:** [M22-L03](M22.md#m22-l03)

**Learning outcome:** Measure whether memory helps the intended user without leaking other users' data.

**Study estimate:** 1–2 hours guided study + 3–5 hours exercise. These are uncalibrated learner-effort estimates, not measured timings or an implementation schedule.

### Primary readings

- [EVAL: OpenAI evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices) — Task-specific datasets, graders, human calibration, continuous evaluation.
- [NIST: NIST AI risk management framework](https://www.nist.gov/itl/ai-risk-management-framework) — Governance, risk identification, measurement and management.

### Interview question

How do you test personalization without rewarding memorization of the benchmark?

**A strong answer addresses:** User-separated splits; fresh tasks; leakage checks.

Score 0–3 using the [shared interview rubric](../README.md#interview-rubric).

### Production exercise

Run paired tasks with and without memory across synthetic users and deliberately stale records.

**Acceptance criteria:**

- Measure task benefit and stale-memory errors.
- Require zero cross-user record access in fixtures.

**Evidence to submit:**

- Versioned artifact or design specification.
- Baseline or hand-checkable fixture.
- Results or expected-results table including a failure case.
- Decision and limitations note.

**Resources:** CPU/local fixtures or a mocked provider; live service use is optional.
