## M17-L01 — Assemble a grounded answer pipeline

**Delivery:** preview · full lesson contract: not_met · interaction: tested_specialist_engine · artifact: learner_starter

**Prerequisites:** [M12-L04](M12.md#m12-l04), [M16-L04](M16.md#m16-l04)

**Learning outcome:** Define boundaries and contracts across a minimal RAG service.

**Topics:** retrieve; select; construct context; generate; cite; abstain.

**Study estimate:** 2–3 hours guided study + 3–5 hours exercise. These are uncalibrated learner-effort estimates, not measured timings or an implementation schedule.

### Primary readings

- [RAG: Retrieval Augmented Generation paper](https://arxiv.org/abs/2005.11401) — Combining parametric generation with retrieved evidence.

### Interview question

Which part of a RAG pipeline would you change for missing evidence?

**A strong answer addresses:** Ingestion versus retrieval versus generation; diagnosis.

Score 0–3 using the [shared interview rubric](../README.md#interview-rubric).

### Production exercise

Build a small policy assistant using versioned synthetic documents, a fixed relevance set and a mock or local generator.

**Acceptance criteria:**

- Trace each answer to chunks.
- Include unsupported questions and conflicting policies.

**Evidence to submit:**

- Versioned artifact or design specification.
- Baseline or hand-checkable fixture.
- Results or expected-results table including a failure case.
- Decision and limitations note.

**Resources:** CPU/local fixtures or a mocked provider; live service use is optional.

## M17-L04 — Release and maintain RAG

**Delivery:** planned · full lesson contract: not_met · interaction: none · artifact: none

**Prerequisites:** [M17-L03](M17.md#m17-l03), [M25-L04](M25.md#m25-l04)

**Learning outcome:** Define a release gate that tests both retrieval and final answers.

**Topics:** end-to-end evaluation; freshness SLOs; index versions; rollback; feedback.

**Study estimate:** 2–3 hours guided study + 4–6 hours exercise. These are uncalibrated learner-effort estimates, not measured timings or an implementation schedule.

### Primary readings

- [RAG: Retrieval Augmented Generation paper](https://arxiv.org/abs/2005.11401) — Combining parametric generation with retrieved evidence.
- [ML: Made With ML course](https://madewithml.com/courses/mlops/) — Product and systems design, data, training, tracking, tests, versioning, operations.
- [SEARCH: Sentence Transformers retrieve and rerank](https://sbert.net/examples/sentence_transformer/applications/retrieve_rerank/README.html) — Bi-encoder candidates and cross-encoder ranking.

### Interview question

How can an index update cause a regression without a code change?

**A strong answer addresses:** Chunking; embedding; source versions; ranking.

Score 0–3 using the [shared interview rubric](../README.md#interview-rubric).

### Production exercise

Execute a local index rollout with shadow queries, answer-quality checks and a rollback drill.

**Acceptance criteria:**

- Version all pipeline components.
- Require slice gates and demonstrate rollback criteria.

**Evidence to submit:**

- Versioned artifact or design specification.
- Baseline or hand-checkable fixture.
- Results or expected-results table including a failure case.
- Decision and limitations note.

**Resources:** CPU/local fixtures or a mocked provider; live service use is optional.

## Module completion gate

Submit every lesson artifact, answer its interview question, and explain one failure-and-recovery case. A reviewer checks acceptance criteria and labels results as designed, simulated, replayed or measured. A plan or replay is not proof of production performance.

Readings support concepts. Larnix's lesson sequencing, scenarios, questions and acceptance criteria are original curriculum design. Recheck relevant source sections and pin implementation versions when writing the actual lessons.
