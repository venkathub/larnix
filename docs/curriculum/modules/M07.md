## M07-L01 — Trace tokens through a transformer

**Delivery:** planned · full lesson contract: not_met · interaction: none · artifact: none

**Prerequisites:** [M05-L04](M05.md#m05-l04)

**Learning outcome:** Explain the shapes and information flow in a decoder block.

**Topics:** tokenization; BPE; embeddings; positional encodings; attention masks.

**Study estimate:** 2–3 hours guided study + 2–4 hours exercise. These are learner-effort estimates, not an implementation schedule.

**Estimate basis:** Study trace tokens through a transformer; build or analyze: Run tokenizer and tensor-shape inspections for short multilingual support requests using a tiny local model or recorded model traces. Verify: Record character and token counts. Stated prerequisites met; small local fixture or explicitly labeled replay; excludes large training runs and cloud provisioning. Confidence: low; editorial estimate, not learner-measured.

### Primary readings

- [LLM: Hugging Face LLM course](https://huggingface.co/learn/llm-course/en/chapter1/1) — Transformer architectures, tokenizers, fine-tuning, NLP, limitations.
- [ATTN: Attention Is All You Need](https://arxiv.org/abs/1706.03762) — Original transformer architecture and attention mechanism.

### Interview question

Why does token count differ between languages for the same meaning?

**A strong answer addresses:** Tokenizer vocabulary; segmentation; context budget.

Score 0–3 using the [shared interview rubric](../README.md#interview-rubric).

### Production exercise

Run tokenizer and tensor-shape inspections for short multilingual support requests using a tiny local model or recorded model traces.

**Acceptance criteria:**

- Record character and token counts.
- Trace query/key/value shapes and the causal mask.

**Evidence to submit:**

- Versioned artifact or design specification.
- Baseline or hand-checkable fixture.
- Results or expected-results table including a failure case.
- Decision and limitations note.

**Resources:** Tiny/local model, synthetic media, or supplied recorded outputs/profiles; larger GPU or paid-provider runs are optional. Replay analysis cannot establish real hardware performance.

## M07-L04 — Understand capabilities and limits

**Delivery:** planned · full lesson contract: not_met · interaction: none · artifact: none

**Prerequisites:** [M07-L03](M07.md#m07-l03)

**Learning outcome:** Explain why fluent output does not establish factual correctness.

**Topics:** next-token objective; in-context learning; reasoning; hallucination; chat templates; test-time compute and verification; reasoning-model verification budgets.

**Study estimate:** 2–3 hours guided study + 2–4 hours exercise. These are learner-effort estimates, not an implementation schedule.

**Estimate basis:** Study understand capabilities and limits; build or analyze: Compare correct and deliberately mismatched chat serialization using a tiny model or supplied token/output fixtures. Verify: Inspect actual tokenized inputs. Stated prerequisites met; small local fixture or explicitly labeled replay; excludes large training runs and cloud provisioning. Confidence: low; editorial estimate, not learner-measured.

### Primary readings

- [LLM: Hugging Face LLM course](https://huggingface.co/learn/llm-course/en/chapter1/1) — Transformer architectures, tokenizers, fine-tuning, NLP, limitations.
