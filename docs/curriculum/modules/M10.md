## Module outcomes

- Write an unambiguous task prompt and a baseline comparison.
- Design inspectable intermediate outputs without relying on private reasoning traces.
- Change prompts using held-out evidence and documented hypotheses.
- Define behavior when instructions conflict or input is insufficient.

## M10-L01 — Specify tasks and examples

**Delivery:** planned · full lesson contract: not_met · interaction: none · artifact: none

**Prerequisites:** [M09-L04](M09.md#m09-l04)

**Learning outcome:** Write an unambiguous task prompt and a baseline comparison.

**Topics:** instructions; delimiters; zero-shot; few-shot; output criteria.

**Study estimate:** 1–2 hours guided study + 1–3 hours exercise. These are learner-effort estimates, not an implementation schedule.

**Estimate basis:** Study specify tasks and examples; build or analyze: Create and evaluate a prompt set for classifying original equipment-damage reports using recorded or small-model outputs. Verify: Include ambiguous and out-of-domain cases. Stated prerequisites met; small local fixture or explicitly labeled replay; excludes large training runs and cloud provisioning. Confidence: low; editorial estimate, not learner-measured.

### Primary readings

- [CONTEXT: Anthropic context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) — Context selection, compaction, long tasks, external memory.
- [EVAL: OpenAI evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices) — Task-specific datasets, graders, human calibration, continuous evaluation.

### Interview question

When do examples help more than a longer instruction paragraph?

**A strong answer addresses:** Task ambiguity; representative cases; token cost.

Score 0–3 using the [shared interview rubric](../README.md#interview-rubric).

### Production exercise

Create and evaluate a prompt set for classifying original equipment-damage reports using recorded or small-model outputs.

**Acceptance criteria:**

- Include ambiguous and out-of-domain cases.
- Compare against a simple baseline on fixed examples.

**Evidence to submit:**

- Versioned artifact or design specification.
- Baseline or hand-checkable fixture.
- Results or expected-results table including a failure case.
- Decision and limitations note.

**Resources:** CPU/local fixtures or a mocked provider; live service use is optional.
