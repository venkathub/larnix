## Module outcomes

- Turn a product requirement into a scored evaluation contract.
- Construct a reusable evaluation set without tuning on its answers.
- Use model judges only after measuring agreement with human judgments.
- Combine offline results with staged online evidence.

## M25-L01 — Define evaluation contracts

**Prerequisites:** [M01-L02](M01.md#m01-l02), [M03-L04](M03.md#m03-l04), [M02-L04](M02.md#m02-l04)

**Learning outcome:** Turn a product requirement into a scored evaluation contract.

**Topics:** task success; datasets; rubrics; golden cases; slices; failure severity.

**Study estimate:** 1–2 hours guided study + 2–4 hours exercise. These are learner-effort estimates, not an implementation schedule.

### Primary readings

- [EVAL: OpenAI evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices) — Task-specific datasets, graders, human calibration, continuous evaluation.

### Interview question

What makes an evaluation actionable rather than decorative?

**A strong answer addresses:** Release decision; representative tasks; clear denominator.

Score 0–3 using the [shared interview rubric](../README.md#interview-rubric).

### Production exercise

Design an evaluation specification for rental-policy assistance before building the model pipeline.

**Acceptance criteria:**

- Separate critical failures from quality scores.
- Define labels and score denominators.

**Evidence to submit:**

- Versioned artifact or design specification.
- Baseline or hand-checkable fixture.
- Results or expected-results table including a failure case.
- Decision and limitations note.

**Resources:** CPU/local fixtures or a mocked provider; live service use is optional.

## M25-L03 — Calibrate human and model judges

**Prerequisites:** [M25-L02](M25.md#m25-l02)

**Learning outcome:** Use model judges only after measuring agreement with human judgments.

**Topics:** rubrics; pairwise judging; agreement; position bias; judge drift; deterministic checks.

**Study estimate:** 1–2 hours guided study + 2–4 hours exercise. These are learner-effort estimates, not an implementation schedule.

### Primary readings

- [EVAL: OpenAI evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices) — Task-specific datasets, graders, human calibration, continuous evaluation.

### Interview question

How can a judge prefer a fluent wrong answer?

**A strong answer addresses:** Style bias; weak rubric; unsupported reasoning.

Score 0–3 using the [shared interview rubric](../README.md#interview-rubric).

### Production exercise

Run a judge-validation study using shuffled answer order and intentionally plausible errors; compare judge labels with human labels.

**Acceptance criteria:**

- Measure disagreement by slice.
- Retain human adjudication and deterministic checks for objective facts.

**Evidence to submit:**

- Versioned artifact or design specification.
- Baseline or hand-checkable fixture.
- Results or expected-results table including a failure case.
- Decision and limitations note.

**Resources:** CPU/local fixtures or a mocked provider; live service use is optional.

## M25-L04 — Make release decisions

**Prerequisites:** [M25-L03](M25.md#m25-l03)

**Learning outcome:** Combine offline results with staged online evidence.

**Topics:** paired evaluation; confidence intervals; thresholds; regressions; online experiments.

**Study estimate:** 1–2 hours guided study + 2–4 hours exercise. These are learner-effort estimates, not an implementation schedule.

### Primary readings

- [EVAL: OpenAI evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices) — Task-specific datasets, graders, human calibration, continuous evaluation.
- [MLFLOW: MLflow evaluating production traces](https://www.mlflow.org/docs/latest/genai/eval-monitor/running-evaluation/traces/) — Ground truth, scorers, trace reuse, quality investigation.

### Interview question

Why can an offline winner lose in a live experiment?

**A strong answer addresses:** Population shift; user behavior; latency; selection.

Score 0–3 using the [shared interview rubric](../README.md#interview-rubric).

### Production exercise

Produce a paired evaluation report from recorded candidate results and simulate a canary go/no-go decision.

**Acceptance criteria:**

- State uncertainty and minimum sample assumptions.
- Block critical regressions despite average improvement.

**Evidence to submit:**

- Versioned artifact or design specification.
- Baseline or hand-checkable fixture.
- Results or expected-results table including a failure case.
- Decision and limitations note.

**Resources:** CPU/local fixtures or a mocked provider; live service use is optional.

## Module completion gate

Submit all four lesson artifacts, answer the four interview questions, and explain one failure-and-recovery case. A reviewer checks acceptance criteria and labels results as designed, simulated, replayed or measured. A plan or replay is not proof of production performance.

Readings support concepts. Larnix's lesson sequencing, scenarios, questions and acceptance criteria are original curriculum design. Recheck relevant source sections and pin implementation versions when writing the actual lessons.
