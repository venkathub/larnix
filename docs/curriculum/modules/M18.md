## M18-L01 — Retrieve across structured knowledge

**Delivery:** planned · full lesson contract: not_met · interaction: none · artifact: none

**Prerequisites:** [M17-L04](M17.md#m17-l04)

**Learning outcome:** Route structured questions to validated queries and unstructured questions to text evidence.

**Topics:** SQL retrieval; metadata filters; semantic layers; query validation; read-only access.

**Study estimate:** 2–3 hours guided study + 3–5 hours exercise. These are uncalibrated learner-effort estimates, not measured timings or an implementation schedule.

### Primary readings

- [SQL: PostgreSQL tutorial](https://www.postgresql.org/docs/current/tutorial.html) — Queries, joins, transactions, window functions.
- [OWASP: OWASP LLM application risks](https://genai.owasp.org/llm-top-10/) — Injection, disclosure, supply chain, poisoning, outputs, agency, consumption.

### Interview question

Why is generated SQL correctness more than syntactic validity?

**A strong answer addresses:** Schema meaning; permissions; joins; resource limits.

Score 0–3 using the [shared interview rubric](../README.md#interview-rubric).

### Production exercise

Build a read-only rental analytics prototype with query validation, row limits and a fixture database.

**Acceptance criteria:**

- Test unauthorized tables and misleading joins.
- Compare numeric answers against deterministic fixtures.

**Evidence to submit:**

- Versioned artifact or design specification.
- Baseline or hand-checkable fixture.
- Results or expected-results table including a failure case.
- Decision and limitations note.

**Resources:** CPU/local fixtures or a mocked provider; live service use is optional.

**Acceptance criteria:**

Submit every lesson artifact, answer its interview question, and explain one failure-and-recovery case. A reviewer checks acceptance criteria and labels results as designed, simulated, replayed or measured. A plan or replay is not proof of production performance.
