# M06 — Data engineering and dataset quality

[All modules](../INDEX.md) · [Learning path](../LEARNING_PATH.md) · [Source register](../SOURCES.md) · [Teaching design](../TEACHING_DESIGN.md)

**Status:** in_progress · **Depth:** core · **Track:** T1

**Entry prerequisites:** [M02-L04](M02.md#m02-l04), [M04-L02](M04.md#m04-l02)

7 lesson specifications follow. Each lesson will use a concrete problem, prediction, interactive explanation, worked example, inline checks and failure investigation before production and interview practice. Follow the teaching design for accessibility and original visual treatment. Delivery status is stated per lesson; a preview is not a completed lab. Complete the evidence package for each exercise; live deployment is not required. Later lessons may introduce an additional cross-module prerequisite.

## Module outcomes

- Specify data contracts across training and serving pipelines.
- Create a labeling process with measurable quality controls.
- Trace a model result to the exact source records and transformations.
- Propagate data changes without silently retaining forbidden records.
- Separate a scheduler from a processing engine and recover a failed partition without duplicating output.
- Reproduce a prediction with only features that were available when the decision occurred.
- Compare label acquisition strategies without contaminating the independently labeled evaluation set.

## M06-L05 — Orchestrate repeatable data processing

**Delivery:** planned · full lesson contract: not_met · interaction: none · artifact: none

**Prerequisites:** [M06-L04](M06.md#m06-l04), [M02-L06](M02.md#m02-l06)

**Learning outcome:** Separate a scheduler from a processing engine and recover a failed partition without duplicating output.

**Topics:** pipeline DAGs; Airflow-style orchestration; idempotent tasks and backfills; Spark dataframes; Ray data processing; partitioning and shuffles.

**Study estimate:** 2–3 hours guided study + 4–6 hours exercise. These are learner-effort estimates, not an implementation schedule.

**Estimate basis:** Study orchestrate repeatable data processing; build or analyze: Build a local partitioned rental ETL pipeline with a manifest and interrupted task; compare a single-process reference with a small Spark or Ray run. Verify: Reruns produce identical row counts and checksums. Stated prerequisites met; small local fixture or explicitly labeled replay; excludes large training runs and cloud provisioning. Confidence: low; editorial estimate, not learner-measured.

### Primary readings

- [AIRFLOW: Airflow architecture overview](https://airflow.apache.org/docs/apache-airflow/stable/core-concepts/overview.html) — Workflow scheduling and execution boundaries.
- [SPARK: Spark SQL and DataFrames](https://spark.apache.org/docs/latest/sql-programming-guide.html) — Distributed dataframe execution and data sources.
- [RAYDATA: Ray Data documentation](https://docs.ray.io/en/latest/data/data.html) — Parallel data processing and batch inference.

### Interview question

Why does adding an orchestrator not make a dataframe operation distributed?

**A strong answer addresses:** Control plane versus compute engine; Task and partition boundaries; Shuffle costs and idempotent writes.

Score 0–3 using the [shared interview rubric](../README.md#interview-rubric).

### Production exercise

Build a local partitioned rental ETL pipeline with a manifest and interrupted task; compare a single-process reference with a small Spark or Ray run.

**Acceptance criteria:**

- Reruns produce identical row counts and checksums.
- Recover one failed partition without a full rebuild.
- Record skew and shuffle observations; local mode is not a cluster benchmark.

**Evidence to submit:**

- Versioned code or analysis with environment and input checksum.
- Hand-checkable baseline and comparison outputs.
- Injected failure, diagnosis and corrected rerun.
- Decision, resource assumptions and limitations.

**Resources:** Small original CPU/local fixture; hosted services and accelerators optional. Record simulation, replay or measurement honestly.
