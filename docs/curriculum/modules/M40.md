Complete the evidence package for each exercise; live deployment is not required. Later lessons may introduce an additional cross-module prerequisite.

## Module outcomes

- Choose a recommendation architecture and guard against biased feedback.
- Use predictive models for quantities and language models for grounded explanation.
- Combine deterministic checks with generated interpretations in an auditable workflow.
- Choose action boundaries and executable validation for operational assistants.
- Evaluate a recommender against a popularity baseline while controlling temporal leakage and feedback bias.
- Compare a forecasting model with a seasonal baseline using only data available at each forecast origin.

## M40-L06 — Forecast with rolling evidence

**Delivery:** planned · full lesson contract: not_met · interaction: none · artifact: none

**Prerequisites:** [M40-L05](M40.md#m40-l05)

**Learning outcome:** Compare a forecasting model with a seasonal baseline using only data available at each forecast origin.

**Topics:** time-series forecasting; seasonal naive baselines; lag and rolling features; rolling-origin validation; forecast horizon; prediction intervals; exogenous feature availability.

**Study estimate:** 2–3 hours guided study + 4–7 hours exercise. These are learner-effort estimates, not an implementation schedule.

**Estimate basis:** Study forecast with rolling evidence; build or analyze: Forecast synthetic weekly rental demand with rolling origins; compare a seasonal-naive baseline and a fitted model, then inject unavailable future weather. Verify: Reject unavailable future covariates. Stated prerequisites met; small local fixture or explicitly labeled replay; excludes large training runs and cloud provisioning. Confidence: low; editorial estimate, not learner-measured.

### Primary readings

- [FORECAST: Forecasting: Principles and Practice, author textbook](https://otexts.com/fpp3/) — Time-series patterns, temporal evaluation, forecasting baselines and uncertainty.
- [LEAK: scikit-learn common pitfalls](https://scikit-learn.org/stable/common_pitfalls.html) — Leakage, preprocessing consistency, reproducibility.
- [PANDAS: pandas introductory tutorials](https://pandas.pydata.org/docs/getting_started/intro_tutorials/index.html) — Dataframe selection, joins, reshaping and aggregation.

### Interview question

Why can a random train/test split flatter a demand forecaster?

**A strong answer addresses:** Neighboring observations leak time structure; Horizon-specific validation; Future covariates may be unavailable.

Score 0–3 using the [shared interview rubric](../README.md#interview-rubric).

### Production exercise

Forecast synthetic weekly rental demand with rolling origins; compare a seasonal-naive baseline and a fitted model, then inject unavailable future weather.

**Acceptance criteria:**

- Reject unavailable future covariates.
- Report errors by horizon with prediction-interval assumptions.
- Keep a reproducible backtest table and explain one structural-break failure.

**Evidence to submit:**

- Versioned code or analysis with environment and input checksum.
- Hand-checkable baseline and comparison outputs.
- Injected failure, diagnosis and corrected rerun.
- Decision, resource assumptions and limitations.

**Resources:** Small original CPU/local fixture; hosted services and accelerators optional. Record simulation, replay or measurement honestly.

## Module completion gate

Submit every lesson artifact, answer its interview question, and explain one failure-and-recovery case. A reviewer checks acceptance criteria and labels results as designed, simulated, replayed or measured. A plan or replay is not proof of production performance.
