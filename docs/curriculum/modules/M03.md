## M03-L01 — Reason with vectors

**Prerequisites:** [M02-L01](M02.md#m02-l01)

**Learning outcome:** Compute similarity and diagnose shape or normalization mistakes.

**Topics:** dot product; norms; cosine; matrix shapes; projections.

**Study estimate:** 1–2 hours guided study + 2–4 hours exercise. These are learner-effort estimates, not an implementation schedule.

### Primary readings

- [MATH: Dive into Deep Learning preliminaries](https://d2l.ai/chapter_preliminaries/index.html) — Linear algebra, calculus, automatic differentiation, probability.
- [FAISS: Faiss research and documentation](https://github.com/facebookresearch/faiss/wiki) — Similarity metrics, approximate indexes, IVF, HNSW, quantization.

### Interview question

When do cosine and dot-product rankings disagree?

**A strong answer addresses:** Vector magnitude; normalization; model objective.

Score 0–3 using the [shared interview rubric](../README.md#interview-rubric).

### Production exercise

Create and execute a hand-checkable similarity notebook for five synthetic document vectors.

**Acceptance criteria:**

- Include zero vectors and unequal norms.
- Compare manual and library calculations.

**Evidence to submit:**

- Versioned artifact or design specification.
- Baseline or hand-checkable fixture.
- Results or expected-results table including a failure case.
- Decision and limitations note.

**Resources:** CPU/local fixtures or a mocked provider; live service use is optional.

## M03-L04 — Compare experiments honestly

**Prerequisites:** [M03-L03](M03.md#m03-l03)

**Learning outcome:** Decide whether a measured improvement supports a release.

**Topics:** sampling; confidence intervals; bootstrap; paired tests; power; multiple comparisons.

**Study estimate:** 1–2 hours guided study + 2–4 hours exercise. These are learner-effort estimates, not an implementation schedule.

### Primary readings

- [SK: scikit-learn model selection](https://scikit-learn.org/stable/model_selection.html) — Splitting, cross-validation, metrics, tuning.
- [EVAL: OpenAI evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices) — Task-specific datasets, graders, human calibration, continuous evaluation.

### Interview question

Is a two-point win on a small benchmark enough to ship?

**A strong answer addresses:** Sampling variance; paired comparisons; practical impact.

Score 0–3 using the [shared interview rubric](../README.md#interview-rubric).

### Production exercise

Run a paired comparison of two recorded routing-result sets using bootstrap resampling and a documented release decision.

**Acceptance criteria:**

- Report uncertainty and sample assumptions.
- Prevent selecting a winner on the test set.

**Evidence to submit:**

- Versioned artifact or design specification.
- Baseline or hand-checkable fixture.
- Results or expected-results table including a failure case.
- Decision and limitations note.

**Resources:** CPU/local fixtures or a mocked provider; live service use is optional.
