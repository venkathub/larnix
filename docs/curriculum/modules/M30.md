- Separate untrusted content from application authority.
- Limit damage even when a model selects a harmful action.
- Turn security findings into regression tests and operational ownership.

## M30-L01 — Map assets and trust boundaries

**Delivery:** planned · full lesson contract: not_met · interaction: none · artifact: none

**Prerequisites:** [M02-L04](M02.md#m02-l04), [M01-L04](M01.md#m01-l04)

**Learning outcome:** Identify assets and attacker-controlled inputs before adding mitigations.

**Topics:** threat modeling; identities; tenant data; prompts; tools; model supply chain.

**Study estimate:** 1–2 hours guided study + 2–4 hours exercise. These are uncalibrated learner-effort estimates, not measured timings or an implementation schedule.

### Primary readings

- [OWASP: OWASP LLM application risks](https://genai.owasp.org/llm-top-10/) — Injection, disclosure, supply chain, poisoning, outputs, agency, consumption.

### Interview question

What changes in a threat model when an assistant can call tools?

**A strong answer addresses:** Action authority; untrusted content; data flows.

Score 0–3 using the [shared interview rubric](../README.md#interview-rubric).

### Production exercise

Create a threat model for a document assistant with optional account actions.

**Acceptance criteria:**

- Map entry points and sensitive sinks.
- Rank concrete abuse cases by impact and likelihood.

**Evidence to submit:**

- Versioned artifact or design specification.
- Baseline or hand-checkable fixture.
- Results or expected-results table including a failure case.
- Decision and limitations note.

**Resources:** CPU/local fixtures or a mocked provider; live service use is optional.

**Acceptance criteria:**

## M30-L04 — Verify controls and respond

**Delivery:** planned · full lesson contract: not_met · interaction: none · artifact: none

**Prerequisites:** [M30-L03](M30.md#m30-l03)

**Learning outcome:** Turn security findings into regression tests and operational ownership.

**Topics:** red teaming; abuse monitoring; incident response; audit logs; deletion; disclosure; content moderation; abuse rate limits; moderation appeals and human escalation.

**Study estimate:** 2–3 hours guided study + 4–6 hours exercise. These are uncalibrated learner-effort estimates, not measured timings or an implementation schedule.

### Primary readings

- [OWASP: OWASP LLM application risks](https://genai.owasp.org/llm-top-10/) — Injection, disclosure, supply chain, poisoning, outputs, agency, consumption.
- [NIST: NIST AI risk management framework](https://www.nist.gov/itl/ai-risk-management-framework) — Governance, risk identification, measurement and management.
- [JAILBREAK: JailbreakBench](https://arxiv.org/abs/2404.01318) — Adversarial-user threat models and robustness evaluation.
- [HAX: Microsoft human AI interaction guidelines](https://www.microsoft.com/en-us/haxtoolkit/ai-guidelines/) — User expectations, corrections, feedback, recovery.

### Interview question

How do you know a prompt-injection fix solved the underlying problem?

**A strong answer addresses:** Reproducible exploit; enforced boundary; variants.

Score 0–3 using the [shared interview rubric](../README.md#interview-rubric).

### Production exercise

Run a synthetic cross-tenant exposure drill and produce a red-team report with reproduction, containment and regression evidence.

**Acceptance criteria:**

- Reproduce using synthetic records.
- Define access revocation, evidence retention and regression coverage.

**Evidence to submit:**

- Versioned artifact or design specification.
- Baseline or hand-checkable fixture.
- Results or expected-results table including a failure case.
- Decision and limitations note.

**Resources:** CPU/local fixtures or a mocked provider; live service use is optional.

## Module completion gate

Submit every lesson artifact, answer its interview question, and explain one failure-and-recovery case. A reviewer checks acceptance criteria and labels results as designed, simulated, replayed or measured. A plan or replay is not proof of production performance.

Readings support concepts. Larnix's lesson sequencing, scenarios, questions and acceptance criteria are original curriculum design. Recheck relevant source sections and pin implementation versions when writing the actual lessons.
