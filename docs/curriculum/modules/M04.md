# M04 — Machine-learning fundamentals

[All modules](../INDEX.md) · [Learning path](../LEARNING_PATH.md) · [Source register](../SOURCES.md) · [Teaching design](../TEACHING_DESIGN.md)

**Status:** in_progress · **Depth:** core · **Track:** T1

**Entry prerequisites:** [M03-L04](M03.md#m03-l04), [M02-L04](M02.md#m02-l04)

7 lesson specifications follow. Each lesson will use a concrete problem, prediction, interactive explanation, worked example, inline checks and failure investigation before production and interview practice. Follow the teaching design for accessibility and original visual treatment. Delivery status is stated per lesson; a preview is not a completed lab. Complete the evidence package for each exercise; live deployment is not required. Later lessons may introduce an additional cross-module prerequisite.

## Module outcomes

- Select an interpretable baseline and an appropriate objective.
- Detect contamination before trusting reported performance.
- Choose a decision threshold based on operational costs.
- Explain whether a failure needs better data, features or model capacity.
- Choose a classical family using data geometry, leakage-safe preprocessing and measured resource tradeoffs.
- Select a model using a bounded validation search without spending the test set.
- Use attribution to debug a model while showing its dependence on correlated features and background data.

**Delivery:** planned · full lesson contract: not_met · interaction: none · artifact: none

**Learning outcome:** Use attribution to debug a model while showing its dependence on correlated features and background data.

**Topics:** permutation feature importance; SHAP; LIME; local versus global attribution; correlated features; explanation stability.

**Study estimate:** 2–3 hours guided study + 3–5 hours exercise. These are learner-effort estimates, not an implementation schedule.

**Estimate basis:** Study explain predictions without claiming causality; build or analyze: Explain two predictions from a rental-risk classifier; compare permutation importance, SHAP and a local surrogate under correlated inputs. Verify: Keep the model and explanation background versioned. Stated prerequisites met; small local fixture or explicitly labeled replay; excludes large training runs and cloud provisioning. Confidence: low; editorial estimate, not learner-measured.

### Primary readings

- [SHAP: A Unified Approach to Interpreting Model Predictions](https://arxiv.org/abs/1705.07874) — Feature attribution and additive explanations.
- [LIME: Why Should I Trust You? Explaining the Predictions of Any Classifier](https://arxiv.org/abs/1602.04938) — Local surrogate explanations and their limitations.
- [CLASSICAL: scikit-learn supervised learning](https://scikit-learn.org/stable/supervised_learning.html) — Linear models, nearest neighbors, SVM, naive Bayes and ensembles.

### Interview question

Can a large SHAP value justify changing that feature to improve an outcome?

**A strong answer addresses:** Attribution is not intervention; Background distribution matters; Correlated inputs can split or distort credit.

Score 0–3 using the [shared interview rubric](../README.md#interview-rubric).

**Acceptance criteria:**

- Keep the model and explanation background versioned.
- Show a misleading attribution case.
- Measure sensitivity to background choice and disclose the non-causal interpretation.

**Evidence to submit:**

- Versioned code or analysis with environment and input checksum.
