## Module outcomes

- Select an interpretable baseline and an appropriate objective.
- Detect contamination before trusting reported performance.
- Choose a decision threshold based on operational costs.
- Explain whether a failure needs better data, features or model capacity.

## M04-L01 — Establish supervised baselines

**Prerequisites:** [M03-L04](M03.md#m03-l04), [M02-L04](M02.md#m02-l04)

**Learning outcome:** Select an interpretable baseline and an appropriate objective.

**Topics:** linear and logistic regression; trees; boosting; task metrics.

**Study estimate:** 1–2 hours guided study + 2–4 hours exercise. These are learner-effort estimates, not an implementation schedule.

### Primary readings

- [ML: Made With ML course](https://madewithml.com/courses/mlops/) — Product and systems design, data, training, tracking, tests, versioning, operations.
- [SK: scikit-learn model selection](https://scikit-learn.org/stable/model_selection.html) — Splitting, cross-validation, metrics, tuning.

### Interview question

Why might a boosted tree beat an LLM on structured records?

**A strong answer addresses:** Data type; signal; cost; evaluation.

Score 0–3 using the [shared interview rubric](../README.md#interview-rubric).

### Production exercise

Train and evaluate two late-return classifiers on synthetic tabular rental records, including an interpretable baseline.

**Acceptance criteria:**

- Compare against majority prediction.
- Document feature availability at decision time.

**Evidence to submit:**

- Versioned artifact or design specification.
- Baseline or hand-checkable fixture.
- Results or expected-results table including a failure case.
- Decision and limitations note.

**Resources:** CPU/local fixtures or a mocked provider; live service use is optional.

## M04-L02 — Protect the evaluation boundary

**Prerequisites:** [M04-L01](M04.md#m04-l01)

**Learning outcome:** Detect contamination before trusting reported performance.

**Topics:** splits; cross-validation; leakage; preprocessing; temporal and group splits.

**Study estimate:** 1–2 hours guided study + 2–4 hours exercise. These are learner-effort estimates, not an implementation schedule.

### Primary readings

- [LEAK: scikit-learn common pitfalls](https://scikit-learn.org/stable/common_pitfalls.html) — Leakage, preprocessing consistency, reproducibility.
- [SK: scikit-learn model selection](https://scikit-learn.org/stable/model_selection.html) — Splitting, cross-validation, metrics, tuning.

### Interview question

How can random splitting leak customer identity?

**A strong answer addresses:** Repeated entities; temporal leakage; preprocessing fit.

Score 0–3 using the [shared interview rubric](../README.md#interview-rubric).

### Production exercise

Construct a deliberately leaking ticket dataset, measure the inflated result, and repair its split and preprocessing strategy.

**Acceptance criteria:**

- Demonstrate the leak.
- Keep the final holdout untouched during repair.

**Evidence to submit:**

- Versioned artifact or design specification.
- Baseline or hand-checkable fixture.
- Results or expected-results table including a failure case.
- Decision and limitations note.

**Resources:** CPU/local fixtures or a mocked provider; live service use is optional.

## Module completion gate

Submit all four lesson artifacts, answer the four interview questions, and explain one failure-and-recovery case. A reviewer checks acceptance criteria and labels results as designed, simulated, replayed or measured. A plan or replay is not proof of production performance.

Readings support concepts. Larnix's lesson sequencing, scenarios, questions and acceptance criteria are original curriculum design. Recheck relevant source sections and pin implementation versions when writing the actual lessons.
