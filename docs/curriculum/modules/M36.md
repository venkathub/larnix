## M36-L01 — Account for training memory

**Prerequisites:** [M05-L03](M05.md#m05-l03), [M08-L02](M08.md#m08-l02), [M33-L03](M33.md#m33-l03)

**Learning outcome:** Estimate training memory before selecting hardware.

**Topics:** parameters; gradients; optimizer states; activations; precision; gradient accumulation.

**Study estimate:** 1–2 hours guided study + 3–6 hours exercise. These are learner-effort estimates, not an implementation schedule.

### Primary readings

- [FSDP: PyTorch FSDP2 tutorial](https://docs.pytorch.org/tutorials/intermediate/FSDP_tutorial.html) — Sharded training, initialization, mixed precision, memory behavior.
- [ZERO: DeepSpeed ZeRO tutorial](https://www.deepspeed.ai/tutorials/zero/) — Optimizer, gradient and parameter sharding.

### Interview question

Why does optimizer memory exceed parameter memory for many training setups?

**A strong answer addresses:** State tensors; precision; master weights.

Score 0–3 using the [shared interview rubric](../README.md#interview-rubric).

### Production exercise

Build a memory-accounting worksheet for a hypothetical transformer configuration.

**Acceptance criteria:**

- Separate persistent and activation memory.
- State precision and optimizer assumptions.

**Evidence to submit:**

- Versioned artifact or design specification.
- Baseline or hand-checkable fixture.
- Results or expected-results table including a failure case.
- Decision and limitations note.

**Resources:** Tiny/local model, synthetic media, or supplied recorded outputs/profiles; larger GPU or paid-provider runs are optional. Replay analysis cannot establish real hardware performance.
