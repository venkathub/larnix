## M27-L01 — Instrument meaningful traces

**Delivery:** planned · full lesson contract: not_met · interaction: none · artifact: none

**Prerequisites:** [M09-L04](M09.md#m09-l04), [M25-L04](M25.md#m25-l04)

**Learning outcome:** Define a trace schema linking user-visible outcomes to internal work.

**Topics:** trace IDs; spans; retrieval; model calls; tools; token usage; correlation.

**Study estimate:** 1–2 hours guided study + 3–4 hours exercise. These are learner-effort estimates, not an implementation schedule.

**Estimate basis:** Study instrument meaningful traces; build or analyze: Instrument an end-to-end trace for a fixture-based policy query that invokes a lookup tool. Verify: Propagate correlation IDs. Stated prerequisites met; small local fixture or explicitly labeled replay; excludes large training runs and cloud provisioning. Confidence: low; editorial estimate, not learner-measured.

### Primary readings

- [OTEL: OpenTelemetry GenAI observability](https://opentelemetry.io/blog/2026/genai-observability/) — Model and tool spans, usage, latency, telemetry content.

### Interview question

Which span data would explain a slow agent response?

**A strong answer addresses:** Queueing; provider time; tools; retries; critical path.

Score 0–3 using the [shared interview rubric](../README.md#interview-rubric).

### Production exercise

Instrument an end-to-end trace for a fixture-based policy query that invokes a lookup tool.

**Acceptance criteria:**

- Propagate correlation IDs.
- Record duration and outcome without storing secrets.

**Evidence to submit:**

- Versioned artifact or design specification.
- Baseline or hand-checkable fixture.
- Results or expected-results table including a failure case.
- Decision and limitations note.

**Resources:** CPU/local fixtures or a mocked provider; live service use is optional.
