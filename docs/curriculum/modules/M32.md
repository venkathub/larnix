## M32-L01 — Select models for a workload

**Delivery:** planned · full lesson contract: not_met · interaction: none · artifact: none

**Prerequisites:** [M09-L04](M09.md#m09-l04), [M25-L04](M25.md#m25-l04), [M01-L02](M01.md#m01-l02)

**Learning outcome:** Build a workload-specific shortlist using measured evidence.

**Topics:** task fit; capabilities; context; latency; hosting; licenses; evaluation; reasoning-model selection; verifier reliability.

**Study estimate:** 1–2 hours guided study + 3–5 hours exercise. These are learner-effort estimates, not an implementation schedule.

**Estimate basis:** Study select models for a workload; build or analyze: Execute a bake-off among a small local model and two recorded or mock hosted-model profiles, labeling simulated results clearly. Verify: Use identical tasks and constraints. Stated prerequisites met; small local fixture or explicitly labeled replay; excludes large training runs and cloud provisioning. Confidence: low; editorial estimate, not learner-measured.

### Primary readings

- [ML: Made With ML course](https://madewithml.com/courses/mlops/) — Product and systems design, data, training, tracking, tests, versioning, operations.
- [TTC: Scaling LLM Test-Time Compute Optimally](https://arxiv.org/abs/2408.03314) — Inference-time compute allocation and verification tradeoffs.

### Interview question

Why might a leaderboard leader be the wrong production choice?

**A strong answer addresses:** Task distribution; constraints; cost; operational fit.

Score 0–3 using the [shared interview rubric](../README.md#interview-rubric).

### Production exercise

Execute a bake-off among a small local model and two recorded or mock hosted-model profiles, labeling simulated results clearly.

**Acceptance criteria:**

- Use identical tasks and constraints.
- Separate measured results from assumed vendor claims.

**Evidence to submit:**

- Versioned artifact or design specification.
- Baseline or hand-checkable fixture.
- Results or expected-results table including a failure case.
- Decision and limitations note.

**Resources:** CPU/local fixtures or a mocked provider; live service use is optional.

## M32-L02 — Calculate complete unit economics

**Delivery:** planned · full lesson contract: not_met · interaction: none · artifact: none

**Prerequisites:** [M32-L01](M32.md#m32-l01)

**Learning outcome:** Estimate end-to-end cost with transparent assumptions.

**Topics:** input and output tokens; cached input; retries; retrieval; review labor; cost per success; test-time compute budgets; cost per verified success.

**Study estimate:** 2–3 hours guided study + 2–4 hours exercise. These are learner-effort estimates, not an implementation schedule.

**Estimate basis:** Study calculate complete unit economics; build or analyze: Build a reproducible cost worksheet for 1,000 synthetic support tasks using parameterized prices. Verify: Include failed tasks and human review. Stated prerequisites met; small local fixture or explicitly labeled replay; excludes large training runs and cloud provisioning. Confidence: low; editorial estimate, not learner-measured.

### Primary readings

- [VLLM: vLLM documentation](https://docs.vllm.ai/en/latest/) — Serving, batching, quantization, caching, speculative decoding, parallelism.

- [TTC: Scaling LLM Test-Time Compute Optimally](https://arxiv.org/abs/2408.03314) — Inference-time compute allocation and verification tradeoffs.

### Interview question

**A strong answer addresses:** Failure retries; verbosity; human handling.

Score 0–3 using the [shared interview rubric](../README.md#interview-rubric).
