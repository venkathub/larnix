## M23-L01 — Understand protocol boundaries

**Delivery:** planned · full lesson contract: not_met · interaction: none · artifact: none

**Prerequisites:** [M20-L04](M20.md#m20-l04), [M09-L04](M09.md#m09-l04)

**Learning outcome:** Explain what MCP standardizes and what remains application policy.

**Topics:** host; client; server; lifecycle; capabilities; JSON-RPC; protocol versions.

**Study estimate:** 1–2 hours guided study + 2–3 hours exercise. These are uncalibrated learner-effort estimates, not measured timings or an implementation schedule.

### Primary readings

- [MCP: Model Context Protocol specification](https://modelcontextprotocol.io/specification/2026-07-28) — Versioned protocol, tools, resources, prompts, capabilities, authorization.

### Interview question

Does MCP decide whether a tool action is authorized?

**A strong answer addresses:** Protocol versus host policy; identity; consent.

Score 0–3 using the [shared interview rubric](../README.md#interview-rubric).

### Production exercise

Draw a textual sequence for initialization, capability negotiation and a tool call.

**Acceptance criteria:**

- Identify all trust boundaries.
- Pin the researched specification version in the implementation plan.

**Evidence to submit:**

- Versioned artifact or design specification.
- Baseline or hand-checkable fixture.
- Results or expected-results table including a failure case.
- Decision and limitations note.

**Resources:** CPU/local fixtures or a mocked provider; live service use is optional.
