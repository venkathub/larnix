## M11-L01 — Design output schemas

**Delivery:** planned · full lesson contract: not_met · interaction: none · artifact: none

**Prerequisites:** [M09-L04](M09.md#m09-l04), [M10-L01](M10.md#m10-l01)

**Learning outcome:** Design a schema that separates missing evidence from a negative result.

**Topics:** JSON Schema; enums; optionality; nullability; constrained generation.

**Study estimate:** 1–2 hours guided study + 2–3 hours exercise. These are learner-effort estimates, not an implementation schedule.

**Estimate basis:** Study design output schemas; build or analyze: Implement a rental-return extraction schema and validators for missing dates and ambiguous damage severity. Verify: Validate schemas and domain constraints separately. Stated prerequisites met; small local fixture or explicitly labeled replay; excludes large training runs and cloud provisioning. Confidence: low; editorial estimate, not learner-measured.

### Primary readings

- [STRUCT: OpenAI structured outputs](https://developers.openai.com/api/docs/guides/structured-outputs) — Schema constraints, refusals, parsing, tool versus response schemas.

### Interview question

Why does valid JSON not imply a correct business decision?

**A strong answer addresses:** Syntactic validity; semantic validity; source evidence.

Score 0–3 using the [shared interview rubric](../README.md#interview-rubric).

Implement a rental-return extraction schema and validators for missing dates and ambiguous damage severity.

**Acceptance criteria:**

**Evidence to submit:**
